01Workflow·Intermediate

Superpowers

A comprehensive library of proven techniques for a stronger, more reliable coding agent workflow.

Use when At the start of a new task, before any code, when you want spec brainstorming, worktree isolation, bite-sized planning, and test-driven development.

Avoid when Dispatched as a single-purpose subagent on an isolated task, or when the user tells the agent to bypass skill workflows.

How to use it
  1. Read the repository’s setup guide for your coding agent and install the supported integration.
  2. Start with brainstorming to clarify the problem and agree on a design.
  3. Move through planning, implementation, testing, and review using the relevant skills.
Example prompt

Use Superpowers to help me plan and implement a settings page. Clarify the requirements first, propose a design, then break the work into small, testable steps.

21Workflow·Advanced

pstack

Poteto's official Cursor plugin that turns Cursor into a real engineering team, helping you write less but higher quality code with rigorous engineering principles and fearless parallelism via /poteto-mode and its 23 playbooks.

Use when At the start of a demanding task such as reproducing defects, tracing performance bottlenecks, or overnight autonomous work needing empirical verification.

Avoid when In workflows built on heavy upfront planning and spec-first stages, which the author eschews, or in non-Cursor harnesses lacking bugbot and automations.

How to use it
  1. In Cursor run /add-plugin pstack (in Claude Code: /plugin marketplace add cursor/plugins, then /plugin install pstack@cursor-plugins).
  2. Run /setup-pstack, pick a reasoning budget and choose your models.
  3. Start any rigorous task with /poteto-mode and let it pick a playbook, then verify the result with concrete evidence.
Example prompt

/poteto-mode this PR has a subtle bug where the scroll drifts every 750ms even when idle. Repro first, then fix and verify.

03Quality·Beginner

Karpathy Skills

A single behaviour guide distilled from common LLM coding pitfalls.

Use when During a non-trivial coding task where models tend to assume silently, add speculative abstractions, edit unrelated code, or skip verifiable test loops.

Avoid when On trivial tasks such as a typo fix or obvious one-liner, where the added caution and verification loops cost speed for no gain.

How to use it
  1. Read the behaviour guide in the repository.
  2. Follow its instructions for adding the guide to your agent’s project context.
  3. Ask the agent to state assumptions, make minimal changes, and verify the result.
Example prompt

Follow the Karpathy Skills guide while fixing this bug. State your assumptions, keep the change focused, avoid speculative abstractions, and explain how you verified the fix.
